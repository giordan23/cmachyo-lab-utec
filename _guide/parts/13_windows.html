Paso 14

Validación de los comandos en Windows: análisis profundo

20 min de lectura

Cada comando de esta guía, su versión para Windows PowerShell 5.1, y cómo se verificó. El análisis completo, con los experimentos, está en docs/ANALISIS_WINDOWS.md.

📖 Tres niveles de evidencia
  • Medido: se ejecutó y se observó el resultado (en macOS, simulando la condición de Windows cuando aplica).
  • Analizado: lo revisa un programa (el analizador de _guide/build.py o una prueba de pytest) en cada compilación de la guía.
  • Conocimiento general: comportamiento documentado de Windows/PowerShell, no reproducido aquí.

Límite declarado: no se ejecutó ningún comando en un Windows real ni en PowerShell. Si algo falla en tu equipo, el paso 15 explica cómo reportarlo.

3 · Docker Desktop en Windows

  • Motor WSL 2 (Settings → General → "Use the WSL 2 based engine"). Docker Desktop debe estar abierto antes de docker compose.
  • Montajes de archivos: ./prometheus/prometheus.yml y ./grafana/… se montan desde Windows. Funcionan desde C:\labs\…; evita carpetas de OneDrive (bloqueos durante la sincronización).
  • Puertos ocupados: si docker compose up dice "port is already allocated", busca qué proceso usa el puerto:
TerminalmacOS / Linux
lsof -i :8000
PowerShellWindows (PowerShell)
Get-NetTCPConnection -LocalPort 8000 -State Listen | Select-Object OwningProcess

4 · El analizador de comandos

Cada vez que se compila esta guía, _guide/build.py revisa todos los bloques de comandos y la compilación falla si encuentra, en un bloque de Windows: &&, ||, touch, export, source, \ de continuación, python3, pip suelto, cp/ls/cat/grep/rm, mkdir -p, $(…), sudo, curl sin .exe, nano/open/lsof o python -c; y en un bloque de macOS: cmdlets de PowerShell, $env:, rutas \Scripts\, curl.exe o notepad. También exige que los bloques macOS/Windows vayan en pares.
