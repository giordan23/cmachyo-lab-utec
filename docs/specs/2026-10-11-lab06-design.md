# Lab 06 — Asesor de ventas → Enrutamiento semántico → Agente analista de riesgo (RAG) → Aprobación humana

**Fecha:** 2026-10-11 · **Programa:** UTEC Posgrado × Caja Huancayo — IA para desarrollo de software
**Estado:** diseño para revisión (no implementado)

> Todos los datos, clientes y reglas son **ficticios**. El PDF de políticas NO es la política real de Caja Huancayo.

## 1. Objetivo

Un asesor de ventas registra una solicitud de producto bancario (crédito). El sistema:

1. Recibe el **formulario del asesor** (primera pregunta): datos estructurados del cliente + pregunta libre.
2. **Enruta semánticamente** la pregunta libre con **Jev (TypeSafe)**: una pregunta de tipo `choice` cuyas opciones son las rutas; Jev devuelve la ruta elegida, su `confidence` y las probabilidades por opción. Bajo el umbral → ruta de respaldo. **API key real** (`TYPESAFE_API_KEY`).
3. Un **agente especialista analista de riesgo** consulta un **RAG** construido sobre un **PDF de reglas** y propone un dictamen con **OpenAI** (LLM + embeddings, **API key real** `OPENAI_API_KEY`).
4. Un **analista humano** aprueba / rechaza / modifica en una **web HTML simple**.
5. El **asesor** recibe la respuesta final del agente (fundamentada en el RAG) con la decisión del analista.
6. Todo se **monitorea con Prometheus y Grafana**.
7. Todos los comandos se **validan para Windows** (PowerShell 5.1) con un análisis profundo.

**Criterio de éxito:** un alumno en Windows o macOS levanta el lab siguiendo la guía en orden, envía una solicitud, la aprueba como analista, ve la respuesta como asesor y ve las métricas en Grafana; `pytest` pasa en cada paso.

## 2. Arquitectura (enfoque A)

Un solo servicio **FastAPI** + **SQLite** + índice vectorial en memoria (NumPy, embeddings OpenAI) + router **Jev** + LLM **OpenAI** + `prometheus_client`; **Docker Compose** levanta `app`, `prometheus`, `grafana`.

Se descartaron: (B) reutilizar pgvector + OTel del lab-04 (reintroduce el problema `ProactorEventLoop`/psycopg en Windows y 3 contenedores más sin aporte nuevo); (C) frameworks de agentes (rompe la progresión del curso: lab-05 fue ReAct en Python puro).

```
[/asesor  form HTML] --POST /api/solicitudes--> [Router semántico]
                                                  |-- consulta_producto --> [RAG] --> respuesta directa (citas)
                                                  |-- evaluacion_credito --> [Agente riesgo]
                                                  |                            herramientas de cálculo
                                                  |                            + RAG reglas + LLM (propuesta)
                                                  |                            + guardas deterministas
                                                  |                            --> estado PENDIENTE_ANALISTA
                                                  |-- fuera_de_alcance / bajo umbral --> mensaje de derivación
[/analista HTML] --GET cola / POST decisión--> estado APROBADO | RECHAZADO (+ comentario)
[/asesor] --polling GET /api/solicitudes/{id}--> decisión final + justificación
[/metrics] <-- Prometheus <-- Grafana (dashboard aprovisionado)
```

## 4. Formulario del asesor (primera pregunta)

Campos: DNI ficticio (8 dígitos), nombre, edad, ingreso mensual (S/), deuda mensual actual (S/), calificación SBS (Normal, CPP, Deficiente, Dudoso, Pérdida), antigüedad laboral (meses), tipo de trabajador (dependiente/independiente), producto (Crédito Consumo, Crédito MYPE, Crédito Vehicular, Tarjeta…), monto, plazo (meses), **pregunta libre**.
Validación con Pydantic (rangos, enums). El router usa **solo la pregunta libre**; el agente usa campos + reglas.

## 5. Rutas semánticas con Jev (`data/rutas.json`)

Cada ruta tiene: `criterio` (descripción para la pregunta `choice` de Jev; en **inglés**, porque Jev rinde mejor en inglés según su documentación — la `state` sigue en español) y `ejemplos` (para el router de respaldo por embeddings y el set de oro).

- `evaluacion_credito` → agente de riesgo → cola del analista.
- `consulta_producto` → RAG responde directo con citas (sin aprobación).
- `fuera_de_alcance` → respuesta fija de derivación (también si score < umbral).

Umbral (`ROUTER_MIN_CONFIDENCE`) calibrado con `eval/eval_router.py`; la guía advierte que el set de oro es pequeño (calibración optimista).

**Proveedor configurable:** `ROUTER_PROVIDER=jev|embeddings|hash`, `LLM_PROVIDER=openai|mock`, `EMBEDDINGS_PROVIDER=openai|hash`. La guía usa **Jev + OpenAI reales**; los modos sin clave existen para que `pytest` corra sin red y sin costo.

## 6. Estados de una solicitud

`RECIBIDA → (consulta_producto) RESPONDIDA`
`RECIBIDA → (evaluacion_credito) PENDIENTE_ANALISTA → APROBADA | RECHAZADA`
`RECIBIDA → (fuera_de_alcance) DERIVADA`
Analista: puede confirmar o **cambiar** el dictamen del agente; cambiar exige comentario. Decisión idempotente (no se decide dos veces: 409).

## 7. Errores

- Jev falla (401/422/429/529/timeout) ⇒ se usa el router por embeddings como respaldo, se registra `router_fallback_total{motivo}`; 401 al arrancar = mensaje “revisa TYPESAFE_API_KEY”.
- LLM falla / respuesta no parseable ⇒ el agente cae a dictamen `OBSERVAR` construido solo con guardas + reglas recuperadas, y se cuenta en `errores_total{componente="llm"}`.
- Índice ausente o dimensión distinta al embedder ⇒ falla al arrancar con mensaje claro (como lab-04).
- RAG sin chunks sobre el umbral ⇒ el agente no inventa reglas: dictamen `OBSERVAR` "sin regla aplicable".

## 8. Métricas (Prometheus)

- `solicitudes_total{ruta}` · `router_score` (histograma) · `rag_score` (histograma)

- Series pre-inicializadas en cero. Dashboard Grafana aprovisionado por archivo.

## 13. Riesgos conocidos (declarados en la guía)

- **Acceso a Jev:** según fuentes de terceros (sept. 2026) TypeSafe pausó nuevos registros; cuentas existentes funcionan. Alternativas documentadas: Vercel AI Gateway / OpenRouter (otra URL/clave). Si un alumno no tiene clave, usa `ROUTER_PROVIDER=embeddings`.
- **Esquema de Jev** tomado de documentación de terceros (no de docs.typesafe.ai directamente); se valida con `scripts/verificar_claves.py` con la clave real del usuario. Hasta entonces: “preparado, no probado contra la API real”.
- **Modelos OpenAI** cambian; el nombre del modelo va en `.env`.
- **Privacidad:** se envían datos de solicitudes a terceros (TypeSafe, OpenAI). Solo datos ficticios en el lab; en producción requeriría DPA y anonimización (DNI nunca se envía: se excluye del `state` y del prompt).
- **Claves:** solo en `.env` (en `.gitignore`), nunca en código, logs ni métricas.
